# Hirebase project guide

## What the product does

Hirebase is a two-sided job portal. Job seekers build a profile, browse and save roles, apply with a resume, and follow application decisions. Employers create a company profile, post openings, inspect submitted resumes, and accept or reject applications.

The career analysis tools help a job seeker review information before applying. They do not decide who gets hired:

- **Resume text similarity** on Find Jobs compares the words in an uploaded resume with the words in a job post. It is a search hint, not a qualification score.
- **Resume alignment estimate** on a job details page compares detected job keywords (80% of the estimate) and common resume sections (20%). It is a transparent heuristic, not a score returned by an employer's ATS.
- **Skill comparison** compares skills saved in the seeker's profile with the skills listed in a selected job. It reports listed matches, unlisted skills, and coverage. A missing skill means “not listed on this profile,” not “the person cannot do it.”

## Where users go

| User goal | Page | What happens |
| --- | --- | --- |
| Create an account or sign in | `frontend/register.html`, `frontend/login.html` | Choose seeker or employer at registration. Login identifies the account type from the registered account. |
| Start a job search | `frontend/job-seeker-dashboard.html` | See the job-search workflow and application updates. |
| Find and compare openings | `frontend/search-jobs.html` → `frontend/job-details.html` | Search or filter roles, inspect a job, compare profile skills, and request a resume alignment estimate. |
| Build a seeker profile | `frontend/profile.html` | Save education, experience, and skills, and upload a PDF/DOCX resume. Skill comparison is available from a job details page. |
| Revisit opportunities | `frontend/saved-jobs.html` | Review roles saved from search or details. |
| Hire | `frontend/employer-dashboard.html` | See posted jobs and their applications, open resumes, and record accept/reject decisions. |
| Set up an employer identity | `frontend/employer-profile.html` | Maintain the company information shown with job postings. |
| Publish a role | `frontend/post-job.html` | Create a job with description, location, experience, type, and required skills. |

## How the main flows work

### Job seeker

1. Register as a job seeker and sign in.
2. Complete **My Profile**. Save the skills used by the skill comparison.
3. Upload a PDF or DOCX resume. Java stores the file and asks the Python service to extract text; the extracted text is saved with the resume record.
4. Search jobs. If a resume exists, Find Jobs requests a text-similarity score for each result.
5. Open a job. Compare profile skills with the job's required skills and optionally calculate the resume alignment estimate.
6. Apply. The application points to the resume used at submission. The employer sees it in their dashboard; the seeker sees later decisions in **Your applications**.

### Employer

1. Register as an employer and sign in.
2. Complete the company profile and post a job.
3. Review new submissions from the employer dashboard. The backend checks that the employer owns the job before returning its applicants, downloading an applicant resume, or updating an application decision.
4. Accept or reject an application. The status is saved in MySQL and appears in the seeker's dashboard on its next refresh (up to 30 seconds while open).

## Code and service map

| Location | Responsibility |
| --- | --- |
| `index.html`, `frontend/*.html` | Static pages and navigation. |

### Data relationships

```text
job_seeker ── job_seeker_profiles
     │
     ├── resumes ── applications ── jobs ── employer
     │                                  │        │
     └── saved_jobs ────────────────────┘        └── employer_profiles
```

`applications.status` is the decision shown to the seeker. `Shortlisted` is displayed as **Accepted**, `Rejected` as **Not selected**, and `Applied` as **Under review**.

## Understanding the analysis outputs

- The skill coverage percentage is `matched required skills / all listed required skills`. Skill strings are case-normalized and accept comma, semicolon, pipe, or newline separators. It compares the saved profile skills, not the full resume text.
- Resume alignment is a local heuristic: distinct non-generic terms from the job text are checked against normalized resume text, then combined with whether Experience, Education, and Skills sections are detected. Use the matched/missing terms to understand the estimate; do not treat it as an ATS pass/fail result.
- Text similarity uses TF-IDF and cosine similarity. It measures word overlap and does not understand seniority, context, truthfulness, or hiring intent.

## Run locally

From the project directory, run each service in its own terminal:

```powershell
mvn -q -DskipTests compile
```

```powershell
$dependencies = (Get-Content target\dependencies-classpath.txt -Raw).Trim()
java -cp "target\classes;$dependencies" App
```

```powershell
Set-Location python-ml-service
python app.py
```

```powershell
Set-Location ..
python -m http.server 8000
```

Open `http://localhost:8000/`. MySQL must be running and configured for `DbConnect`; the schema and dependencies must already be set up.

## Current boundaries to understand

- The frontend is plain HTML, CSS, and JavaScript; there is no frontend framework or client-side router.
- Java is the system of record for accounts, jobs, profiles, resumes, saved jobs, and application status. Python only provides text-analysis/extraction endpoints.
- Application decision notices are in-app dashboard updates, refreshed while the page is open. They are not email or push notifications.
- This project is a local prototype. Before exposing it publicly, identity and authorization need to be enforced with server-side sessions/tokens rather than trusting role IDs stored in browser local storage; upload size/type limits and production server configuration also need deployment review.
